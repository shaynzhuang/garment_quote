# 历史记录筛选 — 设计文档

日期：2026-07-16
状态：已确认，待实现

## 目标

报价记录存多之后不好找。为历史页增加筛选能力，让用户能按**款号/客户名搜索**、按**客户**、按**月份**快速定位记录。

## 需求

历史列表顶部增加一条筛选条，含三个控件，三者以**逻辑与**组合（同时满足才显示）：

1. **搜索框** 🔍 — 输入即时匹配**款号或客户名**，子串匹配、不区分大小写。
2. **客户下拉** — 默认「全部客户」。选项来自**当前实际有记录的**客户（去重）；没填客户名的记录归到「(未指定)」选项。
3. **月份下拉** — 默认「全部月份」。选项按记录 `savedAt` 的年月自动生成，倒序排列（如 `2026-07`、`2026-06`…）。

## 行为

- 纯前端过滤，**不改动存储结构**。`renderHistory()` 先取全部记录，套用当前筛选后再渲染。
- 进入历史页时**重建**客户/月份下拉选项，使新存的记录反映进去。重建时尽量保留用户已选的值（若该值仍存在于新选项中）。
- 无匹配记录时，显示原有的「暂无记录」空状态。
- **导出**跟随当前筛选：导出的即列表中当前显示的记录。若筛选后为空，沿用原有「暂无记录可导出」提示。
- 删除某条记录后，保持当前筛选不变重新渲染。

## 数据

记录字段无变化。筛选依赖已有字段：

- `styleNo`（款号）— 搜索
- `customerName`（客户名）— 搜索、客户下拉
- `savedAt`（ISO 时间串）— 月份下拉，取前 7 位 `YYYY-MM`

## 代码落点

### `src/storage.js` — 纯函数（便于单测）

新增并导出：

- `filterRecords(records, { search, customer, month })` — 返回过滤后的记录数组。
  - `search`：空/undefined 时不过滤；否则对 `styleNo` 和 `customerName` 做小写子串匹配（任一命中即保留）。
  - `customer`：空/「全部客户」哨兵时不过滤；「(未指定)」哨兵匹配 `customerName` 为空/空白的记录；否则精确匹配。
  - `month`：空/「全部月份」哨兵时不过滤；否则匹配 `savedAt` 前 7 位等于该值。
- `listRecordCustomers(records)` — 从记录去重生成客户名列表（含标记是否存在「未指定」记录）。
- `listRecordMonths(records)` — 从记录生成去重、倒序的 `YYYY-MM` 列表。

哨兵值用空字符串 `''` 表示「全部」，避免与真实客户名/月份冲突；「未指定」用一个不可能作为客户名的常量（如 `'__UNSPECIFIED__'`）。

### `src/index.template.html`

历史页（`#page-history`）列表上方加入筛选条：搜索 `<input>`、客户 `<select>`、月份 `<select>`。

### `src/app.js`

- 在 `els` 中登记三个新控件。
- 新增 `applyHistoryFilter()`：读取三个控件值 → `filterRecords` → 渲染。
- `renderHistory()` 改为：取全部记录 → 重建下拉选项（保留已选值）→ 调用 `filterRecords` → 渲染过滤结果。
- 三个控件监听 `input`/`change` → 重新渲染。
- 导出按钮改为导出**当前过滤后**的记录。

### 构建

改完 `src/` 后运行 `npm run build` 重新生成 `index.html`。

## 测试（`src/storage.test.js`）

- `filterRecords` 按客户名精确过滤
- 「未指定」哨兵归类空客户名记录
- 按月份过滤（`savedAt` 前 7 位）
- 搜索匹配款号
- 搜索匹配客户名
- 搜索子串 + 大小写不敏感
- 三者组合（逻辑与）
- 空结果返回空数组
- `listRecordMonths` 去重且倒序
- `listRecordCustomers` 去重

## 非目标（YAGNI）

- 不做排序选项（列表已按保存时间倒序）。
- 不做日期范围精确选择（月份下拉已够）。
- 不持久化筛选状态（切走再回来重置为「全部」即可）。
